# A1 上游注释——工作站/生产环境执行命令（本机不跑的原因见下）

## 为什么本机不跑 KEGG 比对
本机无 blastp/diamond 可执行文件，且 KEGG 比对库不可得：
- KOfam profiles.tar.gz（HMM 方案）实测 1.5 GB，本机到 genome.jp 实测速度 ~20 KB/s，
  需约 22 小时（2026-10-20 实测，见 `scripts/运行日志_A1_20261020.txt`）；
- 盐湖项目的 KEGG 注释本来就是在工作站 6 上跑的（源文件
  `KEGG_des_env_kegg_e-5_num1_similarity30.tsv` 即 blastp 输出，参数 e-5/num1/similarity30）。

用户 MAG 的生产注释应在工作站 6（/media/HD2/QXJ/ran/）执行，命令与盐湖数据完全同参，保证口径一致：

## blastp（与盐湖数据同参数）
```bash
# 输入：本交付夹 A1_MAG_thetaverse/<MAG名>_pyrodigal.faa（基因预测产物，本机已生成）
blastp -query <MAG>_pyrodigal.faa -db kegg \
       -evalue 1e-5 -max_target_seqs 1 \
       -outfmt '6 qseqid sseqid pident length mismatch gapopen qstart qend sstart send evalue bitscore stitle' \
       -num_threads 16 -out <MAG>_kegg_e-5_num1_similarity30.tsv
```
若用 diamond（更快，注意阈值换算）：
```bash
diamond blastp -d kegg.dmnd -q <MAG>_pyrodigal.faa \
       -e 1e-5 -k 1 --id 30 --threads 16 \
       --outfmt 6 qseqid sseqid pident length mismatch gapopen qstart qend sstart send evalue bitscore stitle \
       -o <MAG>_kegg_e-5_num1_similarity30.tsv
```

## 回传后的 ThetaVerse 分析
```bash
python scripts/run_A1_mag_thetaverse.py --hits <MAG>_kegg_...tsv   # 落表+氮循环过程谱（脚本见本交付夹 scripts/）
```
回传表直接放入 A1 文件夹后重跑 `run_A1_mag_thetaverse.py`，下游（read_kegg_hits 落表、
氮循环过程映射、多样性）与本次交付输出同构。

## 本机交付的替代注释口径（如实声明）
本机用 UniProt 精确肽匹配 / NCBI blastp(swissprot) 获取 KO，属于**演示级注释**：
精确肽匹配只覆盖与 Swiss-Prot 完全一致的蛋白，覆盖率低于全量比对；输出
`annotation_evidence_匹配溯源.tsv` 逐行记录了每条 KO 的方法与 accession，未做任何推断填充。
